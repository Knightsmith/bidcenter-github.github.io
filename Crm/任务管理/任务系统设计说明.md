# 任务系统设计说明

> 所属模块：CRM 任务管理
> 文档版本：v1.2
> 编写日期：2026-09-16
> 本次修订：新增「任务状态」独立字段与「逾期判定规则」；新增「任务列表筛选」「领导视图」「实现方式」「页面清单」章节

---

## 一、概述

任务系统是 CRM 场景下的任务管理模块，用于统一承载**系统分发**、**系统触发**与**销售自建**三类任务。

核心能力：

| 能力 | 说明 |
|---|---|
| 查看客户 | 由任务直接跳转至对应客户详情页 |
| 处理任务 | 单条处理或聚合批量处理 |
| 多任务聚合 | 同一客户存在多条未完成任务时，可聚合查看 |
| 批量处理 | 聚合视图下对所有未完成任务统一处理 |
| 列表筛选 | 今日（默认）/ 过期 / 未来 / 全部，并支持按客户、按分类筛选 |
| 领导视图 | 按「当前响应负责人」筛选查看，并提供报表页统计 |
| 原型实现 | HTML 静态页面 + Shadcn 组件库，每页一个独立 HTML 文件 |

## 二、任务组成字段

| 字段 | 类型 | 说明 |
|---|---|---|
| 提醒时间 | 时间 | 任务触发提醒的时间点 |
| 任务类型 | 枚举 | 取值见「三、任务分类」 |
| 客户名称 | 文本 | 任务归属客户 |
| 相关联系人 | 文本 / 多选 | 任务创建时预设的联系人，可与实际联系人不同 |
| 实际联系人 | 文本 | 处理任务时填写的实际联系对象，必填 |
| 任务说明 | 文本 | 任务内容描述 |
| 处理结果 | 枚举 | 已处理 / 下次联系 |
| 任务状态 | 枚举 | 独立字段：待处理 / 待跟进 / 已处理 / 已逾期，见「五、任务状态」 |
| 当前响应负责人 | 文本 | 任务当前的处理责任人，领导视图按此维度筛选 |

**相关联系人与实际联系人的关系**

| 维度 | 相关联系人 | 实际联系人 |
|---|---|---|
| 填写时机 | 任务创建时预设 | 处理任务时填写 |
| 填写方 | 任务发起人 / 系统 | 任务处理人 |
| 是否必填 | 否（创建时预设） | 是（处理任务必填） |
| 取值范围 | 该任务涉及的联系人集合，可为多个 | 本次实际沟通的联系人，可为相关联系人中的一人，也可为其他人员 |
| 二者关系 | 预设范围 | 本次实际执行结果 |

> 二者相互独立：**任务发起人与实际联系人可能为两个人**（例如系统派发或他人创建任务，由本人实际联系客户）。

## 三、任务分类

任务分为三大类：**新发任务**、**系统任务**、**自建任务**。

### 3.1 新发任务

| 项 | 说明 |
|---|---|
| 来源 | 系统分发客户 |
| 特点 | 由系统将客户直接分配至销售人员，形成待办任务 |

### 3.2 系统任务

| 子类型 | 优先级 |
|---|---|
| 活动报名 | 高 |
| 会员升级 | 高 |
| 中标追踪 | 高 |
| 项目追踪 | 中 |
| 邮件关闭 | 中 |
| 功能使用超限 | 中 |

### 3.3 自建任务

| 子类型 | 说明 |
|---|---|
| 临时任务 | 销售按当下需要临时创建 |
| 重复任务 | 按固定周期重复触发的任务 |
| 撞单任务 | 因客户撞单产生的协同处理任务 |

### 4.2 处理任务

| 场景 | 交互流程 |
|---|---|
| 单条处理 | 任务列表中直接点击「处理任务」→ 选择实际联系人 → 填写处理结果 → 提交 |
| 聚合处理 | 同一客户存在多条未完成任务时，点击「处理任务」进入**聚合视图**，可查看该客户全部未完成任务并**批量处理** |

**聚合批量处理规则**

| 项 | 规则 |
|---|---|
| 触发条件 | 同一客户存在 ≥ 2 条未完成任务 |
| 结果设置 | **统一设置一个处理结果**（已处理 / 下次联系），该客户下所有未完成任务共用 |
| 联系时间 | 选择「下次联系」时，**一次性设置一个联系时间**，多条任务共用 |
| 实际联系人 | 批量处理时统一选择一个实际联系人 |
| 提交方式 | **一次性提交**，同步更新该客户下全部未完成任务 |

## 五、任务状态

任务状态为**独立字段**，用于驱动列表筛选与统计，与「处理结果」解耦。

| 状态 | 说明 |
|---|---|
| 待处理 | 任务已创建，尚未处理 |
| 待跟进 | 处理结果为「下次联系」，等待到达联系时间 |
| 已处理 | 处理结果为「已处理」，任务关闭 |
| 已逾期 | 已超过逾期判定时间且仍未处理 |

**与处理结果的关系**

| 维度 | 任务状态 | 处理结果 |
|---|---|---|
| 性质 | 独立字段，反映任务当前所处阶段 | 处理任务时填写的结论，二选一 |
| 变更时机 | 由系统按规则自动流转 | 由销售在处理任务时提交 |
| 对应关系 | 未处理 → 待处理；下次联系 → 待跟进；已处理 → 已处理；超时未处理 → 已逾期 | 已处理 / 下次联系 |

## 六、逾期判定规则

以任务的**发起时间**为基准判定：

| 发起时间 | 逾期规则 |
|---|---|
| 当天 18:00 前发起 | 逾期截止为**当天 24:00**，超过 24:00 仍未处理即计为**逾期** |
| 当天 18:00 后发起 | 当天仍显示在**今日任务**中，但**不纳入次日逾期任务**（次日照常作为今日任务处理） |

> 逾期任务在列表中归入「过期任务」筛选，状态置为「已逾期」。

| 指标 | 说明 |

## 九、处理结果规则

| 处理结果 | 后续动作 |
|---|---|
| 已处理 | 任务关闭 |
| 下次联系 | 必须设置联系时间，任务转为**待跟进**状态 |

## 十、关键规则

1. 一个客户可拥有多个不同类型的任务。
2. 处理任务时**必须选择实际联系人**；实际联系人默认可取自相关联系人，也可另选他人。
3. 相关联系人与实际联系人相互独立，任务发起人与实际联系人可能为两个人。
4. 处理结果二选一：**已处理** / **下次联系**；选择「下次联系」时，联系时间为必填项。
5. 聚合批量处理采用「统一结果 + 统一联系时间 + 一次性提交」方式。
6. 「查看客户」统一跳转至客户详情页-重构.html。
7. 任务状态为独立字段，由系统自动流转，与处理结果解耦。
8. 逾期以发起时间为基准判定，18:00 前发起当天 24:00 截止，18:00 后发起不计入次日逾期。
9. 任务列表默认展示「今日任务」，领导视图在此基础上支持按当前响应负责人筛选。
