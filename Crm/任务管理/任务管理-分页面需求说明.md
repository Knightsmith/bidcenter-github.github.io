### 0.3 全局业务规则（五页必须一致）

**R1 逾期判定（18:00 规则）**

- 提醒时间在 18:00 **之前**发起的任务：逾期截止 = 提醒日**次日 00:00**（即当天 24:00）；状态仍为「未处理」且超过截止 → 判为「已逾期」。
- 提醒时间在 18:00 **及之后**发起的任务：**顺延一个工作日**处理，逾期截止 = **发起日次日的 24:00**。
  例：昨天 18:00 后发起 → 今天仍计入今日任务，**今天 24:00 之后**才判为「已逾期」（即不纳入次日白天的逾期判定）。
- 状态为「已处理」的任务不参与逾期计算（`effStatus` 直接返回原状态）。
- 状态体系只有三态：**未处理** / **已逾期**（未处理的一个形式，超截止时间未处理，表明需优先处理）/ **已处理**；不存在「待跟进」状态。

**R2 任务归 Tab 规则**（按提醒时间 `remind` 归档）

- **今日任务** = 提醒日期 = 今天（**含今天 18:00 后的任务**）∪ 提醒日期 = 昨天且时间 ≥ 18:00（顺延任务）；
- **逾期任务** = 按 R1 判定为「已逾期」的任务（昨天 18:00 **前**的任务今天即入此列；昨天 18:00 **后**的今天仍在今日，明天 00:00 起入此列）；
- **计划任务** = 提醒日期 > 今天；
- 新建任务按联系时间自动归入对应 Tab，并实时刷新各 Tab 计数。

**R3 徽标规范（类型徽标按类型分组着色）**

| 颜色   | 适用类型                                        | 变体值                             |
| ---- | ------------------------------------------- | ------------------------------- |
| 🔴 红 | 注册新分、系统新分、会员升级、客户咨询、活动报名、企业缺失                    | `destructive` / `badge-danger`  |
| 🟠 橙 | 单次拜访、周期回访、撞单任务、额度不足（自建/催办类）                        | `warning`（`#F59E0B` 白字）         |
| 🔵 蓝 | 其他一切（新发任务、中标提醒、项目提醒、功能咨询、邮件关闭、功能使用超限、临时任务等） | `primary` / `badge-default`（兜底） |

- 实现要求：颜色由「类型名 → 变体」映射字典（`TASK_TYPE_VARIANT` / `TASK_TYPE_BADGE`）驱动，**行数据不携带颜色字段**；查不到的类型一律兜底蓝色。
- 状态徽标独立于类型徽标：未处理=浅实心、已逾期=红、已处理=绿（以各页 `STATUS_*` 字典为准）。
- 会员徽标：**VIP 会员=琥珀实心**、付费会员（高级 / 标准）=蓝色实心、免费会员=红色描边。

**R4 Toast 提示**：重要操作成功后 `showToast(title, desc)`，3200ms 自动消失，同屏最多 3 条。

**R5 页面跳转**：统一 `PAGES = { list, agg, lead, report }` + `goPage(k)`；跳 CRM 客户页为**新窗口**并携带 `?customerId=&customer=&from=<来源页>`。

**R6 数据同源**：任务数据在各页独立内嵌，但同一任务 ID 的核心字段（提醒时间、类型、说明、状态）必须跨页一致；新增演示数据须同步到所有相关页面。

## 1. 客户详情页（客户详情页-重构.html）

### 1.1 页面定位

单客户的 360° 视图页：公司资料、主账号信息、任务、在线开通/订阅、联系人、记录管理集中一屏展示。

### 1.2 页面结构（自上而下）

1. 顶栏（快捷工具、删除此客户等）
2. 公司信息区（编辑面板：合并 / 修改 / 拆分）
3. 常用操作栏（销售推进、合同订单、客户服务、财务票据、客户运营、资料管理）
4. 主账号信息总览（左右各 9 项字段）
5. **任务区域**（本模块重点，见 1.3）
6. 功能 Tab 组（在线开通 / 订阅管理 / 结构化数据包 / 数据服务 / 采招大数据 / 追踪信息）
7. 相关联系人账户（5 行，可展开详情）
8. 记录管理（快捷添加记录 + 记录分类 Tab）

### 1.3 任务区域要求

- **三个 Tab**：今日任务 / 逾期任务 / 计划任务，各自独立数据集，Tab 上实时显示计数 `(n)`。
- 表格列：提醒时间 | 任务类型 | 联系人 | 任务说明 | 任务状态 | 操作。
- 类型徽标按 R3 着色；周期类任务附加「周期」小徽标；18:00 后发起的提醒时间下方标注「18:00后发起」。
- 行操作：未完成 →「处理任务」（新窗口打开任务处理页并携带 `customer/contact/task` 参数）；已处理 →「查看」（打开任务详情弹窗）。
- 卡片右上：「+ 新增」（开新增任务弹窗）、「全部任务」「更多」（二者均**跳任务列表页并按本公司名称检索**，见 2.6 深链）。

### 1.4 「新增任务」弹窗要求

1. 字段：
   - 联系人：下拉选择，可进行输入搜索筛选，选项为该客户联系人（含电话、姓名，会员级别）；
   - 任务类型：单选 radio，三选项 **单次拜访（默认选中）/ 周期回访 / 撞单任务**，各带说明文案；
   - 联系原因：多行文本，必填；
   - 联系时间：`datetime-local`，**必须晚于当前时间**（演示基准 NOW = 2026-09-16 19:30；控件 `min` 与提交校验双重生效），必填；
   - 备注：多行文本，**必填**，提交后写入该任务的备注字段（任务详情弹窗中显示于任务说明下方）。
2. 校验：必填项（联系人 / 联系原因 / 备注）为空、或联系时间早于当前时间时，行内红字错误提示 + `aria-invalid`，聚焦首个错误项。
3. 提交行为：
   - 按联系时间自动归 Tab：**昨天 18:00 后 或 今天（任何时间）→ 今日**；早于昨天、或昨天 18:00 前 → 逾期；晚于今天 → 计划（对应 Tab 计数即时 +1）；
   - 联系时间 ≥18:00 时行内标注「18:00后发起」；
   - 弹窗关闭、Toast「任务已创建」、目标 Tab 与当前 Tab 相同时即时刷新列表；
   - 周期回访任务带数据标记，列表中显示「周期」徽标。
4. 点击遮罩可关闭弹窗。

### 1.5 「任务详情」弹窗要求

展示 8 项任务字段 + 流转记录时间线（创建 → 流转 → 状态末节点），点击遮罩关闭。字段顺序要求：**任务说明在前，完成备注紧随其后（备注在任务说明下面）**。

## 2. 任务列表（任务列表.html）

### 2.1 页面定位

客户经理主工作台：按提醒时间汇总今日/逾期/计划任务，支持三级筛选并驱动任务流转。

### 2.2 页面结构

页头 → 一级 Tab → 筛选卡片 → 任务列表卡片（表格 + 空态 + 分页）→ 任务详情弹窗 → Toast。

### 2.3 Tab 与过滤要求

- **任务定义**：今日任务 = 今日未完成的任务；逾期任务 = 逾期还未处理的任务（已处理的任务不归于逾期）。
- 四个 Tab：**今日任务 / 逾期任务 / 计划任务 / 全部任务**，计数徽标随数据实时计算。
- 过滤规则（R1 + R2）：今日 = `remindDate === TODAY`（**含 18:00 后**）**或** `remindDate === 昨天 且 时 ≥ 18:00`（昨日顺延）；逾期 = `effStatus === 已逾期`；计划 = `remindDate > TODAY`；全部 = 所有未完成任务。
- **默认隐藏已处理任务**；一旦设置任一筛选条件，基准集切换为全量（含已处理）以便查历史。
- 排序：按提醒时间升序。

### 2.4 筛选与分页要求

- 三级筛选：客户名称（模糊）、任务分类（新发任务 / 系统任务 / 自建任务，取自类型字典 category）、任务状态（未处理 / 已逾期 / 已处理）；「重置」一键清空。
- 摘要行：`当前「xx」共 n 条，其中未完成 m 条`。
- 分页：每页 **20 条**，页码当前 ±2、首尾省略、显示「第 x / y 页，共 n 条」；翻页后回到列表顶部。

### 2.5 表格与操作要求

- 表格列：提醒时间 | 任务类型 | 公司名称 | 联系人（**两行显示**：第一行「应联系：姓名 电话」；存在实际联系人时第二行「实际联系：姓名 电话」） | 任务说明 | 任务状态 | 操作。
- 类型徽标按 R3 着色；公司名显示简称 + 会员等级徽标。
- 行操作：「查看客户」新窗口打开**该任务所属公司**的客户详情页（对应客户详情页）；未完成 →「处理任务」（带参跳聚合处理页，单条弹窗不复存在）；已处理 →「查看」（任务详情弹窗，12 项字段，任务说明在前、备注紧随其后，截图与交互细节见 RP 文档页面）。

### 2.6 深链参数

| 参数 | 来源 | 行为 |
| --- | --- | --- |
| `?task=任务ID` | 处理完成回跳等 | 自动切「全部任务」Tab 并滚动高亮该行 |
| `?customer=公司名` | 详情页「全部任务 / 更多」 | 预填客户筛选框并切「全部任务」Tab，按公司名模糊检索 |
| `?date=YYYY-MM-DD` | 报表行「查看」 | 按统计日期静默过滤（不出现在筛选卡 UI），基准集含已处理 |
| `?owner=响应负责人` | 报表行「查看」 | 按负责人静默过滤，与 `date` 叠加生效 |

## 3. 任务处理（任务处理.html）

### 3.1 页面定位

同一客户 + 同一联系人名下**多条未完成任务的聚合批量处理页**（由任务列表/详情页跳入）。

### 3.2 进入与退出要求

- 入口 URL 必须携带 `?customer=客户ID&contact=联系人名`（可选 `task=任务ID`）；缺参或客户不存在 → 自动返回任务列表页。
- 页头按钮：「返回任务列表」「查看客户」（新窗口开 CRM）。

### 3.3 页面结构与功能要求

1. **聚合概览卡**：未完成任务数、公司名称、账号名称、会员类型、当前联系人 + 电话、响应负责人。
2. **任务列表卡**：
   - 表头全选 checkbox；行 checkbox **默认全选**；URL 带 `task=` 时仅选中该条；
   - 列：[全选] | 提醒时间 | 任务类型 | 任务说明 | 任务状态（类型徽标按 R3 着色）；
   - 联动：全选/单选互相同步，右下角显示「已选 x / y 条」；
   - 摘要：`xx 名下共 n 条未完成任务`。
3. **批量处理卡**：
   - 实际联系人 select（固定三项：当前联系人 / 响应负责人 / 其他人员）；
   - 处理结果 radio（已处理 / 下次联系）；选「下次联系」显示下次联系时间（必填）；
   - 备注 textarea（**必填**，行内校验非空 + `aria-invalid`；提交后写入每条勾选任务的备注字段，并进入合并联系记录）。
4. **提交（submitBatch）要求**：
   - 校验：联系人非空、结果必选、条件必填、**至少勾选一条任务**（否则 Toast 提示）；
   - 逐条回填勾选任务：实际联系人、备注、关闭时间/约定时间、状态（已处理 / 未处理；处理结果为「下次联系」时回填约定联系时间、状态保持未处理）；
   - Toast「已批量处理 n 条任务」+ 摘要说明 → 重置表单与错误态 → 概览与列表即时刷新。
5. **边界**：本页只回写任务字段，**并写入联系记录**（记录管理属客户详情页）：多任务批量处理后合并为**一条联系记录**，记录内容含处理结果、实际联系人、约定时间、备注，以及**涉及的任务类型与任务 ID**（演示页以详情页「记录管理」内置假数据呈现）。

## 4. 管理层-任务查看（管理层-任务查看.html）

### 4.1 页面定位

管理层只读总览：按**创建时间**查看任务分布、公司/会员、状态与处理时长，可下钻任务详情，需要提供任务操作，管理层可处理对应下的任务，部门经理可处理部门任务，对应管理层可查看并处理。

### 4.2 页面结构

页头（查看任务报表）→ 4 张统计卡 → 筛选卡片 → 任务列表卡片（表格 + 分页）→ 任务详情弹窗。

### 4.3 统计卡要求

- 四卡：**任务总数 / 已完成 / 未完成 / 已逾期**；
- 数值按 `effStatus` 实时计数，**随筛选条件联动**刷新；
- 未完成 = 未处理 + 已逾期。

### 4.4 筛选、排序与表格要求

- 筛选：公司名称（子串匹配）、完成状态（全部 / 已逾期 / 未处理 / 已处理）、**部门（「大区-部门」拼接去重生成，如北京-客服2部）、当前处理人（由数据中处理人去重生成下拉）**；**部门 → 处理人联动**：选部门后处理人下拉仅剩该部门人员（已选非本部门的自动回「全部处理人」），部门与处理人可叠加筛选；「重置」清空全部（含恢复处理人全量选项）。
- 排序：状态优先级 **已逾期 > 未处理 > 已处理**，同状态按创建时间倒序。
- 表格列：公司名称 | 创建时间 | 任务内容 | 完成时间 | 销售记录（完成备注）| 状态/时长（状态徽标 + 处理时长）| 当前处理人 | 操作。
- 处理时长口径：已完成 = 创建 → 完成时间；未完成 = 创建 → 当前时间（**与逾期豁免解耦**）。
- 逾期行整行底色高亮。
- 分页每页 20 条，与任务列表同规格。
- 摘要：`共 n 条任务，其中已完成 x 条、未完成 y 条`。
- 行操作：「处理」（**未完成任务显示**，带参跳聚合处理页，与任务列表同口径）、「查看客户」（新窗口）、「详情」（只读）。

### 4.5 「任务详情」弹窗要求

字段：公司名称、会员类型、创建时间、完成状态、完成时间、当前处理人、**任务内容、完成备注（备注在任务说明/任务内容下面）** + **流转记录时间线**（程序生成：创建 → 流转至处理人 +15 分钟 → 按终态分支：已处理「完成处理」/ 未处理且处理结果为下次联系「约定下次联系」+60 分钟含约定时间 / 已逾期「任务已逾期」含截止时间 / 否则「等待处理」）。

## 5. 任务报表（任务报表.html）

### 5.1 页面定位

按人日报：统计**每位响应负责人当天**的任务数量与处理情况，高层需要根据部门，一个大部门里会有n个小部门，公司有m个大部门，有对应的部门统计，可以展开收起，部门也需要有统计。

### 5.2 页面结构

页头（标题 + 当前使用者 + 日期选择）→ 4 张指标卡 → 部门树统计卡（树形表格 + 合计行，可展开 / 收起）→ 底部逾期规则说明文案。

### 5.3 功能要求

1. **日期切换**：`datetime` 选择框（默认今天 2026-09-16），改变即全量重算；统计范围 = 提醒日期等于所选日期的任务 **∪ 前一日 18:00 后顺延进入今日的任务**（与 R2 今日口径一致）。
2. **四张指标卡**：
   - 今日任务总数（desc：所选日期）；
   - 未处理（desc：尚未联系客户）；
   - 已逾期（desc：18:00 前发起且超 24:00 未处理）；
   - 已处理（desc：任务已关闭）。
   - 分桶口径与全局 `effStatus` 一致（已处理 / 已逾期 / 其余归未处理）。
3. **部门树形统计表**（高层按部门查看任务）：
   - 组织架构（演示数据）：**3 个大部门，每个大部门 2 个小部门**，现有 3 位负责人分别挂载一个小部门，其余小部门暂无负责人；
   - 层级：大部门（可展开 / 收起）→ 小部门（可展开 / 收起）→ 负责人行，**每一级都输出任务统计**（部门 = 下级求和；负责人 = 任务按客户归属人归集）；
   - **层级视觉区分**：大部门行深灰蓝底（`#E2E2EA`）+ 加粗，小部门行浅灰底（`#F4F4F7`），负责人行白底；缩进 `1rem → 2.75rem → 4.5rem`，行悬停底色同步加深（`data-level` 驱动）；
   - 列：部门 / 负责人 | 今日任务数 | 已处理 | 未处理 | 已逾期 | 操作；
   - 暂无负责人的小部门显示「（暂无负责人）」，统计为 0，无操作按钮；
   - `tfoot` 合计行「合计（3 个大部门 / 6 个小部门 / 3 位负责人）」；
   - 摘要行：`统计日期：xx · 3 个大部门 / 6 个小部门 / n 位负责人 / m 条任务 · 已处理 a · 未处理 b · 已逾期 c`。
4. 行操作「查看」→ 跳转任务列表并携带 **`?date=<统计日期>&owner=<响应负责人>`**，列表页按该日期 + 负责人静默过滤（见 2.6 深链参数）。

### 5.4 边界说明

本页表格**不渲染任务类型列**（类型徽标颜色规则不适用）；如后续增加类型维度，须同步 R3 徽标规范。
